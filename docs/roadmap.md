# FunASR 转写后续方案记录

> 2026-08-15 记录。当前进度：方案 1、2 已实现（见 `scripts/polish_notes.py`），方案 3–5 待做。

## 现状

一次课堂录音（如 `体验改善培训内容.m4a`，约 31 分钟）转写后已产出：

- `notes/<名称>/<名称>.md`：带时间戳、说话人标签的流水账文本
- `notes/<名称>/<名称>.srt`：字幕
- `notes/<名称>/<名称>.json`：FunASR 原始结果（逐句时间戳、说话人、逐字时间戳）

当前 `.md` 只是逐句罗列，缺少纠错、结构和可读性，因此后续按以下方案推进。

## 方案清单

### 1. 文本纠错 + 顺滑（已实现）

- 用 LLM（默认本地 Ollama）对转写文本做：
  - 纠错：同音错字、专业术语（如“工案改善”→“提案改善”、“实急”→“实际”）
  - 顺滑：去口语词、重复（如“呃”“嗯”“以以”）、断句优化
- 保留原句数量、顺序与时间戳，输出 `notes/<名称>/<名称>.整理.md`。

### 2. 生成结构化笔记（已实现）

- 基于纠错后的全文，用 LLM 提炼：
  - 概述、大纲（章节结构）、核心要点、行动项/待办、专有名词与关键词、常见问答
- 输出 `notes/<名称>/<名称>.结构化笔记.md`。

已跑通示例：2026-08-15 用 DeepSeek 处理《体验改善培训内容》（674 句），产出
`notes/体验改善培训内容/体验改善培训内容.整理.md`、`.polished.json` 和 `.结构化笔记.md`（`notes/` 已 gitignore）。

### 3. 音频同步互动笔记（待做）

- 生成 HTML：点击句子跳转到音频对应位置播放、按说话人筛选、关键词定位。
- 数据来源：`notes/<名称>/<名称>.polished.json`（纠错后逐句 + 时间戳）+ 原音频文件。
- 本机可直接打开（`file://`）即可用，无需起服务。

### 4. 搜索 / 问答（待做）

- 把转写内容做成本地可检索知识库（RAG），支持“提案改善有哪九类”这类提问，答案带时间戳。

### 5. 统计与分析（待做）

- 说话人时长占比、关键词频率、重点段落自动提取。

## 实现约定

- 新脚本保持 `scripts/transcribe.py` 的输出结构可被直接消费（每个录音目录内的 `.json` → 后处理）。
- 后续输出格式变化时同步更新 README 与本文档。
- LLM 后端默认本地 Ollama，可通过环境变量切换任意 OpenAI 兼容 API：
  - `LLM_BASE_URL`（默认 `http://127.0.0.1:11434/v1`）
  - `LLM_MODEL`（默认 `qwen3:0.6b`）
  - `LLM_API_KEY`（本地 Ollama 可留空）

## 模型选型（2026-08-15 已确认）

- 本机 Ollama 只有 `qwen3:0.6b`，实测纠错会丢实义内容、漏改术语、重复句子，**不用于正式产出**。
- 已选定 **DeepSeek API**（`deepseek-chat`，OpenAI 兼容），key 保存在项目 `.env`（已 gitignore，不入库）。
- 如需切换后端：编辑 `.env` 或设置 `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`。
